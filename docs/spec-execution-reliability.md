# Spec 精简与执行可靠性

本次修复来自 PFRD-3551 任务 `0d3d3f80-de7b-44f2-bf2d-711cc6e00efe` 的执行日志。

## 行为变化

- 模型函数参数根节点为 object，不再输出根 anyOf。共享字段去重，命令与 payload 的完整联合校验仍由执行器使用原始 Zod 协议执行。默认浏览器工具参数由 13,054 字节降至 7,766 字节（约 41%）。
- 同一执行段中工具 schema 被拒绝的模型不再被后续决策反复选中；新执行允许重新探测。连续两次模型超时触发该模型 5 分钟冷却，保留单次 300 秒上限和显式配置，避免一个决策连续等待五轮。其他模型与凭据不受模型级冷却影响。
- 新 Spec 的 accountRequirements 只收集被测业务对象。明确的后台登录身份被校验拒绝并提示移到 authRole；历史 Spec 重新调度时忽略误列的登录账号需求。业务账号权限测试不会仅因 role 为 admin 被过滤。
- 描述、步骤及普通说明每项最多 300 字，名称最多 100 字；账号用途最多 80 字、数量理由最多 160 字。复杂用例仍可包含必要的额外步骤，验收、观察目标和来源原文不被截断。
- 生成提示要求简单场景合并为通常 3–6 个业务步骤，各字段只表达自己的内容。接口细节保存在验收观察目标，通用账号规则只由平台统一提供；执行目标不再逐账号重复通用规则或数量说明。
- 详情页默认展示简短目标，完整说明可展开；历史任务原始 Spec 与证据不改写。
- 已正常提交验收结果且浏览器关闭已核验时，待核实的写入审计独立折叠展示，不再宣称“已停止自动重试”。执行状态不再仅因残留审计被改写为恢复失败；写入审计和数据保护保留。真正中断或关闭未核验的执行仍显示处理提示。

## 生命周期 Case 的精简表达示例

以下展示表达方式，不是对历史结果的重写：

**目标**：验证两种新增白名单类型的新增、编辑与清理。

**账号**：1 个业务账号；两种类型记录均不存在。

1. 只读核对账号及两种类型的记录不存在。
2. 分别新增两种类型，保持启用并检查新增结果。
3. 按账号和类型筛选，核对记录与启用状态。
4. 分别编辑为禁用，检查列表和编辑回显。
5. 重新启用，检查状态与更新对象一致。
6. 删除本 Case 创建的记录并确认清理完成。

**必要验收**：新增配置正确；筛选和启用展示正确；禁用后列表与回显正确；重新启用正确；必要请求字段符合来源要求。每项在结构化观察目标中保留对象、枚举、字段值和证据要求，不在每个步骤再复制完整请求体。

已提供账号存在目标记录时，仍按前置条件问题记录无法判定，不重新索取账号，不删除既有记录来满足前置条件。

## 验证与边界

验证包含工具参数兼容、原始命令校验、模型切换与超时次数、登录身份与业务对象区分、生成长度限制、复杂步骤保留、收尾审计保护及页面展示。

这些改动不需要数据库迁移。模型上游排队或推理延迟无法由本地代码保证消除；修复限制无效重试和空等。历史任务的账号问题结论不会被改成通过；完整业务复验需先满足数据和登录前置条件。
