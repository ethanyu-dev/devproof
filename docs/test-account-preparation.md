# 测试账号前置准备

Spec 分析同时输出每个 Case 的 `accountRequirements`。按独立业务对象计算最少账号数；能够安全共用账号的类型放在同一角色中。纯界面验证使用空数组，不按验收点数量索取账号。每个角色包含用途、数量、读写方式、业务类型、前置约束和数量依据。

执行流程：Spec 完成 → 展示各 Case / 环境的账号需求 → 用户批量或分批提交 → 原子保存角色分配 → 创建满足条件的 Run → Agent 先进行只读业务前置检查，再执行写入。无需账号的 Case 可先执行。账号是否存在、是否具备特定业务记录等产品约束由执行环境中的前置检查确认；账号格式检查不能替代业务检查。

## 持久化与并发

- `task_case_executions.test_account_plan` 保存需求、版本、等待期限和角色绑定；绑定自然归属于任务、Spec Case、部署环境和执行批次。
- `POST /console/api/tasks/:id/test-accounts` 接收 `submissionId`、`expectedRevision` 和 `{caseExecutionId, slotId, account}` 分配列表。重复提交幂等；旧 Spec、旧批次、已开始调度和过期请求不能改写分配。
- 账号不再预占、互斥或锁定。相同账号可提交到同一 Case 的多个角色、其他 Case、其他任务和重跑任务；手机号、UUID 等别名仅用于识别业务对象，不参与平台占用检查。Spec 中确有必要的身份隔离仍由 Agent 按业务前置条件核验。
- 提交使用任务级事务锁保证表单分配原子性与幂等，其他任务不会因同账号而被拦截。同一 Case 重试自动沿用相同角色的用户账号，重新核对业务前置条件；不读取旧 Run 的释放条件。
- 历史账号声明与恢复审计保留，但不再影响账号分配和执行；旧 execution.account.claim 事件仅作为日志保存，旧 accountConflict 字段读取时忽略。浏览器会话关闭、写入回执与清理台账继续独立工作，允许使用账号不会把未知写入结果改为已核验。
- 历史 Spec 没有结构化需求时兼容识别其测试账号角色，`账号 A/B` 只表示角色，不能被提取成真实账号。重新分析的 Spec 必须输出结构化需求。

## 人工输入与预算

准备账号期间不创建 Run、不占浏览器、不消耗 Case 执行预算；等待本身受 HITL 超时限制。禁用 HITL 时，缺少必要账号的 Case 明确受阻，不能无限排队。准备过期后通过重试 Case 重新准备。

尚未提供账号时保留 TEST_ACCOUNT 多角色协议；用户已提供但账号不存在、不可用、前置记录冲突等情况，不再次请求替换账号，而是记录受影响标准为 INCONCLUSIVE（无法判定），附具体原因和证据，并正常完成 Case。未受影响的标准继续验证；若 Case 本身验证无效账号应被拒绝，则按实际产品行为正常判定。旧任务仍处于人工账号输入时，可以正常提交并恢复。只替换请求的 `slotId`，其余账号、写入回执和清理证据保留。更换账号后重新核验产品结论，旧结论不能直接用于新账号。账号框只接受标识，处置意见使用独立字段。

用户输入的账号与业务响应补充的别名是两条独立路径。响应中的手机号、UUID、邮箱先按账号标识协议清洗、校验并去重；空邮箱、空白字符串、非法文本不能成为关联不同用户的依据。非法执行进度返回带字段路径的 `INVALID_EXECUTION_CHECKPOINT`（HTTP 400），在保存进度前拒绝。

每次有效人工处理后重置执行预算和父任务期限；重复提交不重置。生成 Case 默认执行预算为 1800 秒，已有更大显式预算保留。恢复时使用当前会话所有权及租约检查，丢失会话不能直接恢复为可执行状态。

## 执行稳定性

浏览器点击对被自身展示标签覆盖的关闭态 combobox 定位到同一控件的外层，不强制穿透其他浮层。上下文按实际字节预算裁剪完整工具轮次，最多保留 32 组。已交付的稳定页面观察可保存为带来源的验收事实，随 checkpoint 恢复；它们不自动产生通过结论，也不恢复过期的元素引用。模型须引用证据完成判定。

网络仅供执行 Agent 参考，新 Spec 不生成网络字段验收。历史 Spec 可使用 `networkCitations: [{target, observationId, cursor, requestIndex}]` 引用 `page.network` 中已读取的完整请求，序号从 0 开始。平台绑定原始请求和 NETWORK 证据，并对现有 Spec 中的请求体字段集合、明确命名的 JSON 字段和查询参数做结构化比较；不会用页面文字或截断数据替代网络证据。业务记录台账支持 `/list` 查询路径和 `whitelists` 列表字段，仍要求创建前的完整空结果、同资源成功提交及后续记录才能确认创建归属。

## 部署与验证

先执行 `pnpm prisma:deploy` 应用 `20260915040000_task_test_account_plan` 的新增 JSONB 列，再构建并重启 API / Agent Runtime / Web；浏览器点击修复还需更新本地 Browser Runtime 的构建产物。该迁移不更改历史 Run 结论，也不会自动重跑历史业务用例。

主要回归覆盖结构化协议、空账号 Case、分批分配、幂等预算、同账号跨任务并发提交、历史占用兼容、等待超时、重跑复用、账号问题无法判定、局部人工替换，以及真实浏览器中的 Select 标签遮挡。
