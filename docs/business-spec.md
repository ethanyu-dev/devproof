# 简洁业务 Spec 与执行绑定

新生成的对象状态验收只声明业务对象、预期和必要时机，定位与取证在 Runtime 完成。Agent 协议从 2.23 开始支持此格式；内部保存为 `observationContract.version=3`。浏览器的结构化观察仍是 version 2，沿用 `BROWSER_OBSERVATION_V2_ENABLED` 开关。

## 生成格式

```json
{
  "requirementId": "requirement-1",
  "description": "两种类型的记录均显示启用。",
  "businessCheck": {
    "subjects": ["合规模型映射", "旧版对公转账白名单"],
    "state": { "label": "配置值", "equals": "启用" }
  }
}
```

- `subjects` 是需要分别验证的对象，不是等价名称；每个对象都必须有证据。
- `state` 是共同预期。不同对象允许同为“启用”，不需要把需求句子拼成各自不同的页面文字。
- 默认当前状态；默认值用 `when: INITIAL_AFTER_OPEN`，重新打开用 `REOPENED`，操作后用 `AFTER_ACTION`。业务所要求的时间顺序仍是约束。
- 视觉比较才填写 `compareWith`、`dimensions`。编译器为参照对象保存实际状态和图片，不把被测对象的期望状态强加给参照对象。
- 普通文字发现和接口字面值仍用 `observationTargets`；来源引用证明需求依据，不能代替浏览器证据。业务名称和预期字符串仍检查来源支持。
- 新生成工具不再暴露 scope、controlKind、property、assertionId 等 DOM 契约字段。描述推荐 80 字以内、工具上限 160 字，步骤按业务动作合并。

编译器补齐稳定目标/断言编号、证据种类和视觉参照关系。存储与重试使用固化的契约和摘要，历史 Spec 不会被自动重写。生成来源、引用与完整请求继续归档。

## Runtime 决策与取证

1. 固定上下文只展示简短业务对象、状态和必要时机。Agent 根据当前页面选择导航、筛选、滚动与观察顺序；步骤是业务路线建议，默认值、保存后等因果要求不能跳过。
2. `observe_subject` 接受 criterionId、subject、observationId、scopeRef、identityRef、stateRef。实际值由控制面从同一次规范化捕获读取，Agent 不提交自拟实际值。
3. 绑定要求身份和状态位于同一最小记录行、表单或弹窗，同一 frame/document。下拉选项、搜索输入、过期或截断数据不能作为选中对象。过大的父区域不能把不同记录拼在一起。
4. 默认状态继续检查区域生命周期与被修改节点。手动切换后显示开启，不能证明默认开启。图片比较继续要求两侧图片确实交付给模型，并保存具体比较维度和结论。
5. 事实进入 `objectEvidence`。`record_criterion` 与 `finish_verification` 自动选取本标准已交付的事实和评审，复用同一验证函数；遗漏对象、冲突、无效阶段和未读事实仍不允许通过。
6. 原有 `bind_observation` 留给旧格式；新格式使用业务对象入口。两种格式可以在同一执行中共存。

状态节点与业务字段的语义对应仍由 Agent 结合页面判断；系统检查证据身份、节点关系、实际属性值和覆盖率。对象状态绑定不单独证明账号归属、筛选隔离、写入授权或操作成功，这些业务要求仍需相应证据。网络证据不能替代明确要求的 UI 展示。

## 跨 Step 上下文与收敛

每轮执行状态显示已记录的既有记录、已确认不存在的记录、已记录的创建提交数和本次创建记录数。不会因最近操作窗口滚动而丢失“记录已存在／尚无创建回执”的事实；这里的计数只描述已记录观察，不声称捕获了全部网络流量。

证据提交失败按验收项计数。其他页面变化不再重置该项的纠正次数；连续三次拒绝后保存具体错误并将该项标为无法判定，继续独立项。后续取得有效证据仍可更新结论。所有必需项已收尾时直接结束。

网络引用按已读取的 `page.network` 请求验证，`type=...` 按 URL 查询参数精确比较，重复参数不视为明确值。请求字段不能通过原文子串绕过结构化校验。

## 兼容与验证

- API 对协议 2.23、观察开关开启的生成任务下发新格式；旧 Agent 继续获得旧生成协议。
- 执行新格式需要 `business-checks-v3` 能力及协议 2.23，旧 Agent 不会误领任务。
- 新业务契约复用已有绑定表与证据归档，不新增数据库迁移。区域一致性修复需要 Browser Runtime 0.2.30；结构化观察保留 version 2，并兼容旧快照。
- 重新生成 Spec 才能获得新业务格式；只重跑历史 Spec 会使用其原始要求。
- 回归覆盖两行相同状态、跨行/遗漏对象拒绝、真实不匹配、选项冒充选中值、手动修改冒充默认值、视觉参照、已交付证据自动引用、旧格式及能力协商。
- API 集成测试使用真实浏览器的三种类型弹窗，执行捕获、持久绑定、图片交付、视觉评审和最终验收；不操作实际业务测试账号。

## 数据冲突与人工处置

账号已提供而记录冲突时，执行 Agent 使用 `request_human_input(kind=DATA_PRECONDITION)`。
`context` 包含 `criterionIds` 和 `records: [{id,account,type,evidenceRefs}]`。
平台保留浏览器，界面列出具体记录，用户可以亲自处理或在处置意见中填写“可以先删除上述记录开展后续测试”。
用户答复连同请求范围保存在 `resume` 和 `humanResolutions`，后续重新登录不会丢失先前意见。
请求本身和直接点击交还均不授权删除；Agent 只按明确意见处理请求列出的记录，先重新核对身份，确认删除后重新查询并继续。
同一组冲突收到答复后不重复请求；HITL 禁用、用户拒绝或仍无法处理时，继续独立项，受影响项记录无法判定。
负向无效账号测试继续按原预期判断，不触发修复数据的人工处置。

独立编辑 Spec 不得无依据要求“目标记录不存在并先新增”。编辑使用获授权的现有测试记录并恢复初始状态；新增仍须确认目标记录缺失。
`record_progress.citations` 支持当前节点 ref，系统解析原文和证据引用；`records[].evidenceRefs` 可以省略。提供观察 ID 的旧调用只在其原文已交付并通过校验后解析为证据 ID。

## 状态与采集一致性

开关验收必须生成布尔预期，列表文案使用字符串。生成阶段拒绝文本形式的开关状态，历史错误契约返回 `STATE_TYPE_MISMATCH`，不将空文本误判为产品失败。
选择外层 dialog/form 时，绑定器根据身份与状态节点归一化到唯一的最小业务范围，跨行状态仍被拒绝。
浏览器保留有界 DOM 变化记录，输出变化节点及 `verifiedScopeNodeIds`。背景变化不会废弃已核实稳定的表单；目标状态变化、节点替换、几何变化及缺失变化历史仍不能通过。
不稳定采集最多额外重采两次，DOM、引用与截图一起更新，业务动作不会重放。
